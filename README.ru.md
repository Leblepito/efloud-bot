## ✨ Обзор

**Efloud Bot** — автоматизированная система торговли фьючерсами, построенная вокруг **Smart Money Concepts (SMC)** — Break of Structure (BoS), Change of Character (CHoCH), Order Block (OB), Fair Value Gap (FVG) и Optimal Trade Entry (OTE) — на цепочке таймфреймов (направление HTF → подтверждение MTF → триггер входа).

Её отличают не сигналы, а **дисциплина вокруг них**:

- **Детерминированный 7-уровневый механизм безопасности** (circuit breaker, позиционные ограничители, защита «осиротевших» позиций, запрет разворота без прибыли, fail-closed защита от проскальзывания входа, предполётная проверка на пустой книге, изолированная маржа) — фильтрует каждый ордер.
- **Сверка с биржей как источником истины** — реализованный PnL читается из income-записей Binance (`realizedPnl − комиссия − funding`), а не из локальных оценок.
- Встроенное **живое измерение edge** — каждый сигнал фиксируется в момент появления, теневым образом разрешается на реальных рыночных данных и отчитывается как **метрики edge за вычетом издержек со статистическими порогами**. Бот честно измеряет собственный edge прямо в продакшене.
- **Круглосуточный мониторинг** (routines watcher) — контроль circuit breaker, маржи, аудит позиций, детекция дрейфа конфигурации и сбор рыночных данных работают в собственном ритме, независимо от торгового цикла.
- **Сопутствующие индикаторы TradingView** (Pine v6) — та же машина состояний SMC, прямо на графике и без перерисовки; для ручного подтверждения или самостоятельного использования.
- **Отказоустойчивый мульти-агентный LLM-слой**, который *советует*, но никогда не переопределяет детерминированные защиты. Нет API-ключа — бот работает без изменений.

> ⚠️ **Предупреждение о рисках.** Это ПО торгует реальными деньгами на деривативах с плечом. Торговля фьючерсами может привести к **полной потере капитала**. Ничто здесь не является инвестиционной рекомендацией. Сначала запускайте на testnet; используйте на свой риск.

## 🏗 Архитектура

Основной поток: **Рыночные данные → SafeOrchestrator → SMC-движок (v1+v2) → Сигнал + Confluence → Риск/Сайзинг → Стек безопасности → OrderManager → Binance**. Команда LLM-агентов стоит *рядом* с конвейером как советник; слой измерения edge (**SignalLedger → Теневой резолвер → edge_report**) работает только на чтение и по умолчанию ВЫКЛЮЧЕН (`signal_ledger.enabled` / `EFLOUD_SIGNAL_LEDGER_ENABLED`); routines watcher наблюдает за всем со стороны. Mermaid-диаграммы — в английском README.

Торговое решение всегда проходит через детерминированный шлюз `can_trade` и стек безопасности — LLM-слой можно отключить в любой момент без какого-либо изменения поведения.

## 🛡 Стек безопасности

| Уровень | Что делает |
|---|---|
| **Circuit Breaker** | Дневные/недельные лимиты убытков + пауза после серии убытков → HALT (сохраняется между перезапусками) |
| **Позиционные ограничители** | Лимит notional на сделку, лимит суммарной экспозиции, границы дистанции SL (опциональный жёсткий отказ выше max ATR), max время удержания, лимит пирамидинга |
| **Защита «осиротевших» позиций** | Находит позиции на бирже, неизвестные локальному состоянию; может выставить защитный SL |
| **Запрет разворота без прибыли** | Блокирует переворот в противоположный сигнал, пока текущая позиция не в прибыли сверх буфера комиссий и проскальзывания |
| **Защита от дрейфа входа (fail-closed)** | Отклоняет вход, если живая цена ушла от якоря сигнала или уже прошла TP1 — и **блокирует вход, если сам фид цены недоступен** |
| **Точность SL/TP + проверка размещения** | Цены округляются по правилам точности биржи (без отказов PRICE_FILTER); после входа повторный запрос, ремонт недостающих ордеров; если SL не подтверждён — позиция закрывается по рынку |
| **Изолированная маржа + One-Way** | ISOLATED маржа + one-way режим принудительно при старте; предполётная проверка `[5/5]` на пустой книге перед любой сменой режима |
| **V2 Shadow fail-closed** | Движок SMC v2 нового поколения по умолчанию в теневом режиме — потерянный ключ конфигурации оставляет его *наблюдателем*, а не трейдером |

Каждый уровень **отказывает безопасно**: худший исход неправильной конфигурации — *прерванный запуск* (без торговли), но никогда — незащищённая живая позиция.

## 📏 Живое измерение edge

Вопрос, которого избегает каждый продавец ботов: *действительно ли сигнал несёт торгуемый edge после издержек?* Efloud Bot отвечает на него о самом себе — непрерывно:

- **SignalLedger** — каждый сигнал при первом появлении (и торгуемый, и наблюдаемый) записывается в идемпотентный JSONL-журнал в момент подтверждения.
- **Теневой резолвер** (каждые 5 минут) — воспроизводит гипотетическое исполнение, разыгрывает гонку SL против TP на минутных данных с консервативным правилом «та же свеча = SL» и вычитает **комиссии + funding + проскальзывание** в R-единицах.
- **Отчёт edge** (ежечасно) — NET-ожидание, win-rate с доверительными интервалами Уилсона, профит-фактор, панель устойчивости к таймаутам, разбивки по измерениям — с честной пометкой `INSUFFICIENT EVIDENCE`, пока выборка мала.

Всё за флагом (`signal_ledger.enabled: false` по умолчанию) и только на чтение. Решения о калибровке (пороги confluence, модели TP) принимаются из этих данных, а не «на глаз».

## 📈 Пакет TradingView (Pine v6)

Два скрипта, зеркалирующие логику SMC v2 бота — **EFloud Signals v2** (индикатор) и **EFloud Strategy v2** (бэктест):

- Полная **машина состояний «жди-подтверждай»**: триггер CHoCH → зона отката (FVG > OB > OTE) → подтверждение поглощением.
- **Оценка confluence 0–100** (MTF CHoCH, HTF FVG, ретест Order Block, OTE, SFP, premium/discount, дневное направление, ввод AI-сентимента) с опциональным фильтром.
- **Без перерисовки по построению** — все данные старших таймфреймов используют последний *закрытый* бар (`[1]`-сдвиг + `lookahead_on`); живые сигналы совпадают с бэктестом.
- Профили горизонта сделки (scalp / mid / long), SL-буфер с учётом волатильности, лестница TP1/TP2, панель на графике и предупреждение о неверном таймфрейме.

Исходники — в [`pine/`](pine/); полная спецификация перевода — в [`pine/PINE_SPEC.md`](pine/PINE_SPEC.md).

## 🤖 Система агентов

Два независимых слоя, оба **аддитивные и отказоустойчивые**:

- **Runtime-команда** (`engine/agents/`) проверяет каждый сигнал в **теневом режиме** (`gating: false`). Вердикты логируются и доступны через `GET /api/ai/agents`. Без `GEMINI_API_KEY` каждый агент возвращает `NEUTRAL`, и бот не затронут; *сбойный* (в отличие от несконфигурированного) агент возвращает `ERROR`, и команда **закрывается в безопасную сторону**.
- **Dev-команда** (`.claude/agents/`) — панель специалистов по сопровождению кода **и** трейдингу: ревью SMC, аудит рисков, квант-анализ, надзиратель уровня фонд-менеджера и дежурный live-ops. Все — **советники**; никто не может ослабить детерминированные защиты.

## 🚀 Быстрый старт

```bash
# 1. Установка
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

# 2. Конфигурация (сначала testnet!)
cp .env.example .env          # задайте BINANCE_API_KEY / SECRET
# отредактируйте config.yaml: testnet: true, dry_run: true

# 3. Запуск
python main.py                # CLI (читает config.yaml)

# 4. Дашборд / API
uvicorn backend.main:app --reload   # /healthz, /api/*, веб-панель

# 5. Мониторинг (опционально, рекомендуется)
python -m scripts.routines.runner watch
```

> **Выход в лайв** требует `EFLOUD_ALLOW_MAINNET=1` и пройденной предполётной проверки:
> `EFLOUD_ALLOW_MAINNET=1 EFLOUD_CONFIG_PATH=configs/config.phase2_1k.yaml python preflight.py` → `[5/5]` должно пройти на **пустой книге**.

## ⚙️ Конфигурация

- `config.yaml` — профиль CLI по умолчанию.
- `configs/config.phase2_1k.yaml` — **активный продакшен-профиль** (backend читает через `EFLOUD_CONFIG_PATH`).

## 📦 Развёртывание

Многосервисный стек **Docker Compose**, проверенный в продакшене на Hetzner VPS за **Caddy** (автоматический TLS):

| Сервис | Роль |
|---|---|
| `efloud-bot` | торговый инстанс V1 + дашборд FastAPI |
| `efloud-bot-long` | второй инстанс (свой кошелёк, свои config/env) |
| `routines-watcher` | мониторинг 24/7 + резолвер/отчёт edge |
| `alerter` / `overseer` / `daily-report` | алерты по логам, супервизия, отчётность |
| `caddy` | TLS-реверс-прокси для дашбордов |

Живые изменения маржи/режима следуют **ранбуку сервисного окна на пустой книге** (стоп → закрыть всё → деплой → предполёт `[5/5]` → старт → подтвердить). См. [`deploy/HETZNER_GUIDE.md`](deploy/HETZNER_GUIDE.md) и [`docs/deployment_guide.md`](docs/deployment_guide.md).
